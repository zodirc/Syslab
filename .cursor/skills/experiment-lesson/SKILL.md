# 实验与课程正文

本文只确定规则。`docs/learn/brief.txt`、`docs/learn/course.txt`、`docs/learn/figures.txt` 和 `docs/learn/media` 中已有内容不作为合格样本。后续审查按本文逐节处理，重写或删除。

适用范围：`brief.txt` 各字段，`course.txt` 的标题和第三栏，动画文件，实验 README 的「实验目的」。

## 1. 口吻

句子给出对象、动作和条件。开篇写领域和对象，然后写操作顺序、字段和核对结果。同一概念只用一个名词。符号、函数、协议字段、错误字符串保持代码中的原文，首次出现时写出它在该机制中的动作。

不写宣传句，不写没有对象和动作的句子。

| 使用 | 不使用 |
|---|---|
| 在 C++ 对象模型中，复制按成员进行。指针成员得到地址 | 浅拷贝是……；名称和含义写在一起 |
| 源存储从 7 改为 9 后，经该地址读到 9 | 它不说明……；它们不说明…… |
| 票据锁按取号顺序进入临界区 | 按号进入 |
| 测试并设置自旋锁用一次原子交换进入临界区 | 测试并设置 |
| 已核对的值 | 有效样本；差值为 0 也说明不了发生或未发生 |
| `sched_yield` 请求调度器选择其他可运行线程 | 以未说明的接口名起句，再写它改变了下一项 |
| Linux 调用 `mmap`，用 `MAP_ANONYMOUS` 与 `MAP_PRIVATE` 建立一段不对应文件的私有地址 | Linux 上该申请是 mmap |

不把一次操作写成接口名。接口名出现时写出调用，以及这次调用改变的对象。

「不是……而是……」不作为一节的组织方式。

```markdown
在 C++ 对象模型中，复制按成员生成新对象。指针成员得到地址，两个对象指向同一块存储。源存储从 7 改为 9 后，经该地址读到 9。另行分配的存储仍为 7。
```

## 2. 机制

一节对应一条机制。背景的第一句用「在……中」写出这条机制所在的领域，例如在 C 语言中，在操作系统中，在内存序中，在 C++ 对象模型中。

随后按操作顺序写这条机制，并写上程序核对的结果。名词和接口名的写法见第 1 节。

审查时判断这一节是否成立。成立的条件是：背景里有一条机制，程序的通过条件核对这条机制的结果。不成立则删除，不改写成占位。

只列出字段名和影响因素、没有上述机制的，不设这一节。`getrusage` 的 `ru_nvcsw` 与负载、时间片、计数粒度并列，属于这种文字。`OS-007` 已从课程删除，不写回。

通过条件只是算术结果，或正文把机制推到另一节的，同样删除。`CPU-002` 调用 `add_six(1, 2, 3, 4, 5, 6)`，通过条件是返回值 21，参数寄存器写在另一节。该节已删除，不写回。

## 3. 图

图是动画，按时间顺序显示该机制的状态变化。文件路径为 `docs/learn/media/<编号>.gif`。页面在文件存在且文件头为 `GIF` 时嵌入。

`figures.txt` 的文字由页面画成静态图。静态图里的字仍是文字，不符合本节对图的规定。

已有动画文件同样接受后续审查，不因文件已经存在而视为合格。

## 4. 重点

`brief.txt` 的字段顺序为：名词、重点、背景、语言、机制、程序、证明。

`重点` 位于 `名词` 与 `背景` 之间。页面先显示背景，再显示课标题。`重点` 在课标题下。

`重点` 按第 1 节书写这一节的机制。不使用疑问句。

## 5. 标题

`course.txt` 每行第二栏是标题，页面以它作为课标题。

标题写出该机制的专业名称，以及该机制作用的对象。

锁一节的标题包含锁的种类，以及线程进入临界区的规则。

「测试并设置」未包含锁，不能用作标题。

「按号进入」是口语，不能用作标题。

「抽象机规定的返回值」没有机制的名称，不能用作标题。

「前六个整数参数的寄存器」没有写出调用约定，不能用作标题。调用约定一节的标题包含约定的名称，以及该约定放置的整数参数。
